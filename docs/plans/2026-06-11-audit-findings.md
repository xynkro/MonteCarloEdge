- Evidence: The only gate on producing the paid MCE recommendation in persist is the seat-local flag `s.assisted === true` (line 149). `assisted` is set once from the user's `edgePass` at createTable:195 / joinTable:222 and is then baked into the serialized AuthTable seat (auth-table-codec spreads every seat field). It is never re-validated against a live read of `users/{uid}.edgePass`. adminSetEdgePass (line 417) flips `edgePass:false` on the user doc but does not touch any seated `assisted` flag. So a player whose Edge Pass is revoked mid-session continues to receive the recommendation payload (written to their own gated hole doc) on every turn until t
- Fix: Re-validate entitlement at rec time rather than trusting the persisted seat flag: in persist, before computing the rec, read the seat owner's `users/{uid}.edgePass` (or stamp the rec gate on a short-lived check) so `assisted` reflects the current entitlement. Alternatively, have adminSetEdgePass(on=false) also clear `assisted` on any seat that uid currently occupies.
