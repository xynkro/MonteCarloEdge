# Product/UX audit — 2026-06-22 (professional app-tester lens)

Six-agent audit (5 senior product/UX testers + a product-lead synthesis) of the *experience* — flows,
friction, conversion, trust — not CSS bugs. 41 recommendations. This is a decision-ready roadmap; UX is

## Your two questions, answered

### Q1 — "Do we still need login to SEE the Store now that payments are Apple/Google IAP?"
**No — and it's now shipped fixed.** ✅ The login-to-browse gate was pure dead weight: Apple/Play own
the payment identity at checkout, and your only hard requirement (credit chips to a Firebase uid) is
*already* enforced at the buy button — every handler (`buyPack`, `buyEdge`, `startEdgePass`, `doRestore`)
calls `ensureSignedIn()`. The store-tile lock blocked window-shoppers for zero benefit.

**The model — browse-open, buy-gated:**
1. **Browse = open.** Done: the Store tile no longer locks; signed-out users see the full catalog,
   Edge Pass value, prices, and the "7-day free trial" line (`renderStore` already handled the
   signed-out state). *Verified in preview.*
2. **Buy/Claim = gated, untouched.** `ensureSignedIn()` stays exactly where it is — sign-in happens
   with *intent* ("I want this"), not as a toll gate.
3. **Same pattern recommended for Play Online** — let people see the lobby read-only, gate at Join/Create.

### Q2 — "How can we improve the overall UX & GUI?" — three levers, in priority order
1. **Collapse friction on the free path.** "Start Training — Free" lands on a 9-field config wall
   (`renderSetup`) with two co-equal primary buttons ("TRAINING MODE" vs "LIVE IN PERSON" — the latter
   an advanced manual tracker that bewilders if mis-tapped). That's ~6 decisions before a card is dealt.
   → Deal a hand immediately with the defaults the app already holds; demote config to a gear; demote
   "Live in Person" to a secondary link.
2. **Stop signalling "locked."** Signed-out Home stacks **four padlocks** (topbar, banner, Play Online,
   Store) when the marquee feature (Train + leak report) is 100% free. → One prompt, reframe locks as
   rewards ("Play Online — rooms with friends →"), make Train the hero, and state the free/paid boundary
   *before* the first lock.
3. **Fix navigation so nothing traps the user** (see the launch blocker below).

## 🚨 Launch blocker — ✅ RESOLVED (2026-06-22)
A single screen-history stack now drives the edge-swipe, the **Android hardware Back** (via
`@capacitor/app`), and fixes the Stats/Leaks dead-ends. Verified in preview + the iOS build compiles
with the plugin. (Original problem, for the record:)
**Android hardware Back closes the entire app from any screen.** There is no `history.pushState`/
`popstate` and no Capacitor `App.backButton` listener anywhere — Android's system Back exits the app
instead of going back. **This is a hard Play Store rejection.** The only back affordance is a left-edge
swipe whose target ids are hardcoded and silently omit Stats & Leaks, so swipe and the on-screen button
disagree. **Fix once, properly:** a single screen-history stack — push on every `S.screen` change; pop
from web `popstate`, native `App.addListener('backButton')`, and the swipe handler alike. This resolves
the Android requirement, the Stats/Leaks dead-ends, and the swipe/button mismatch by construction.

## Bigger bets (high impact, larger effort)
- **Unify navigation on one screen-history stack** (web + Android hardware Back + swipe) — *includes the
  launch blocker above.*
- **Promote the Leak Report to a first-class, glanceable Home feature** — a GTO-accuracy stat strip +
  "See your leaks →". It's your differentiated, retention-driving loop, currently a thin link two taps deep.
- **One identity anchor + dedupe Store entry points** — signed-in Home mutates in ~5 places with no
  single "signed in as X, chips saved" anchor, and has two doors to one Store.
- **Make the recommendation *teach*, not just tell** — plain-words "why this size / equity / pot odds",
  a glossary for read-pill shorthand (capped/reps/polar), and first-hand coachmarks.

## Cross-cutting themes
1. Browse-open, buy-gated — gate at value capture, never at discovery.
2. Time-to-value over configuration — first tap deals a hand.
3. Sell the free, don't shout the locked.
4. One navigation source of truth (web + hardware + swipe).
5. Surface proof of progress (the leak report) to drive daily return.
6. Respect the post-auth & contained-app contract (no required fields post-sign-in; keep content in-app).
